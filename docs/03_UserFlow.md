# 1. Communication Inbox

ユーザーが連携した各種サービスから、通知やメッセージを取得する。

取得したコミュニケーションはサービスごとに分断せず、LINEなどのメッセージアプリに近い一つのトーク一覧画面へまとめて表示する。

## 1.1 Message Classification

AIは受信したメッセージの内容を解析し、以下の二種類に分類する。

- 仕事と思われる内容
- 仕事ではないと思われる内容

AIは案件化を提案したり、ユーザーに行動を促したりしない。

分類結果は、トーク一覧の表示順を整理するためにのみ使用する。

案件化の判断は、必ずユーザーが行う。

## 1.2 Display Order

トーク一覧は、以下の順番で表示する。

1. 進行中の案件に関連付けられているトーク
2. AIが「仕事と思われる内容」と分類したトーク
3. その他のトーク

各グループの中では、最新メッセージの受信日時が新しい順に表示する。

## 1.3 Active Project Pinning

ユーザーがトークを案件化した場合、そのトークは進行中案件として一覧上部へ固定する。

進行中案件に関連付けられたトークは、新しいメッセージの有無や受信日時にかかわらず、その他のトークよりも上部に表示する。

案件に関する以下の処理がすべて完了するまで、固定表示を継続する。

- 業務の実施
- 納品
- 請求書の発行
- 入金確認
- 領収書の発行

領収書の発行が完了した時点で案件を完了状態とし、トークの固定表示を解除する。

## 1.4 Project Creation

ユーザーはトークを開き、内容の確認や返信を行う。

新しい仕事の依頼であるとユーザーが判断した場合は、トーク画面内の「案件化」ボタンを押す。

# 2. Project Creation

ユーザーがトーク画面内の「案件化」ボタンを押すと、案件作成画面を表示する。

AIは案件化の対象となったメッセージやトーク履歴を解析し、入力可能な情報を案件作成画面へ自動反映する。

## 2.1 Project Fields

案件作成時には、以下の情報を登録する。

### 必須項目

- 案件名
- 依頼者
- 仕事内容
- 納期・実施日

### 任意項目

- ギャラ

ギャラは、案件化時点で金額が決まっている場合に入力する。

金額が未定の場合は、空欄のまま案件を作成できる。

案件作成後、ギャラを含む各項目はいつでも編集できる。

## 2.2 AI Autofill

AIはトーク内の情報から、以下の項目を抽出する。

- 案件名の候補
- 依頼者
- 仕事内容
- 納期または実施日
- ギャラ

抽出できた情報は、案件作成画面の入力候補として表示する。

AIが抽出した内容は自動で確定せず、ユーザーが確認・修正したうえで案件を作成する。

AIが情報を特定できなかった項目は空欄で表示する。

必須項目が空欄の場合、ユーザーが入力するまで案件を作成できない。

## 2.3 Project Creation Completion

ユーザーが内容を確認し、「案件を作成」ボタンを押すと案件化が完了する。

案件化に使用したトークは、作成された案件へ関連付ける。

案件化の完了後、そのトークはCommunication Inboxの進行中案件エリアへ移動し、案件が完了するまで上部に表示する。

案件化は必ずユーザーの明示的な操作によって実行される。
